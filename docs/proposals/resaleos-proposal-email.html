Hi team — we run Berlin Houseware, a Shopify storefront built on ResaleOS. We've launched public "seller storefronts": a page for each consignor showing their items, name, and logo (think a mini shop-within-the-shop). Shoppers love a face behind the goods, and it gives consignors a page they'll happily share.

Building it, we hit the same small set of gaps any ResaleOS merchant would hit. Closing them is mostly adding one field and one endpoint, and it would turn "public consignor storefronts" into something every merchant on ResaleOS gets more or less for free.

The gap, in plain English

ResaleOS already knows who each product's consignor is. But the API doesn't hand that back in a way a storefront can use, so today a merchant can't reliably answer two simple questions:

•  "What is this seller's name?" — the product record has the seller's ID but the name comes back empty; the name only appears elsewhere, without the ID to match it to.

•  "Show me this seller and their items." — there's no seller endpoint to ask.

To ship anyway, every integrator ends up building the same workarounds (stitching the name together from other calls, and hand-keeping seller profiles in Shopify). They work — but they're fragile, and they're the same tax on every merchant.

What we're suggesting
Additive, read-only, no breaking changes. Ordered by value-for-effort.
1. Put the consignor's name (with their ID) on the product P0

Include both accountId and name in the consignor object on the product API and product webhook. This one field removes the biggest workaround by itself — no more stitching names together from sales data.

2. Add a consignor endpoint P0

GET /consignors/{accountId} (returns 404 today) giving the seller's public identity — at minimum name + a stable slug, ideally logo, bio, and a verified flag. Lets the seller's profile live in ResaleOS instead of being hand-entered per store.

3. Three follow-ons P1

•  A consignor.updated webhook (you already send product webhooks) — so seller renames appear in real time instead of on a schedule.
•  Filter sales by consignor — for per-seller stats and payout reconciliation.
•  List a consignor's products — so a store can be built straight from ResaleOS.

P0 — DO FIRST
Name-on-product + consignor endpoint. Removes the two big workarounds.
P1 — NEXT
Consignor webhook, sales-by-consignor, consignor's products.
Why it's worth it for ResaleOS

•  A feature every merchant gets. Public consignor storefronts become an out-of-the-box selling point, not a custom build.

•  More GMV on ResaleOS-backed stores. Give consignors a page and they promote it — that traffic flows back to your merchants.

•  Tiny surface area. #1 is a field on data you already send; the rest are read endpoints over data you already hold. No breaking changes.
